# GEO 报告 PDF 交付流程

在画像、评分和核心结论已确认后执行。本流程只改变呈现方式，不改变工作模式边界、事实结论或证据要求。

## 1. 默认交付

- 快速诊断与完整策略默认生成一份中文、带图、可离线打开的 PDF。
- HTML 仪表盘仅在用户明确需要时附加；不能用 HTML 代替 PDF 收尾。
- 推荐文件名：`{品牌}_GEO品牌诊断报告_易读版_{YYYY-MM-DD}.pdf`。
- 最终文件放在当前项目的 `output/pdf/`；中间文件放在 `tmp/pdfs/`。

## 2. 报告结构

快速诊断建议按以下顺序组织；可合并页面，但不要省略证据边界：

1. 封面：品牌、市场、日期、综合分与一句话判断。
2. 核心结论：总分、AI 搜索出现次数、最多 3 项优先动作。
3. 品牌基本情况：已确认、公开证据、暂不确定分别呈现。
4. 五项体检：E-E-A-T + V 雷达图及逐项解释。
5. AI 搜索表现：问题、平台、是否出现品牌、未获取的平台。
6. 品牌公开资料检查：已有、偏弱、缺失。
7. 对标位置：只做当前工作模式允许的深度；定性图必须注明不是性能实测。
8. 行动页：每项都写“做什么 / 为什么”。
9. 证据附录：来源、快照、采集方式、未获取信息与结论有效期。

完整策略可在此基础上增加关键词矩阵、内容规划、竞品深度分析和路线图；持续监测增加周期变化图。

## 3. 白话化规则

- 标题优先说业务含义，不直接使用 `EXECUTIVE SUMMARY`、`BASELINE`、`ASSET GAP` 等英文栏目名。
- `GEO` 第一次出现时解释为：“让 ChatGPT、Gemini 等 AI 在回答相关问题时更容易提到品牌”。
- `AI 可见度` 解释为：“用户问相关问题时，AI 有没有主动推荐或引用品牌”。
- `非品牌查询` 改写为：“用户不输入品牌名、只描述需求时的查询”。
- `缺采` 改写为：“本轮未获取”；并说明“不等于平台一定没有提到品牌”。
- `E-E-A-T + V` 可以保留在方法附注中，但读者看到的主标签使用：真实经验、专业能力、外部认可、可信程度、AI 推荐。
- 红队、黑盒、Agent、benchmark、License、Privacy、Terms、KPI、KOL 等词首次出现时给中文解释；能用准确中文替代时直接替代。
- 英文检索问题保留原文作为证据，同时给出自然中文释义。
- 避免“信任底座、认知空位、可引用资产、第三方权威”等抽象说法；改成具体句子，例如“把团队、隐私政策、开源许可证补齐”“让外部的人帮品牌作证”。

## 4. 图表与口径

- 至少包含 EEAT-V 雷达图和 AI 搜索出现情况；其他图表仅在帮助理解时加入。
- 图表标题、坐标轴、图例使用中文白话；产品名和平台名保留原文。
- `0` 只用于真实完成测试且没有出现品牌的情况；未完成采集的平台必须单独标为“本轮未获取”。
- 定性竞品图必须注明“基于公开介绍，不代表性能实测或市场份额”。
- 分数、样本数、日期和来源必须与 ledger/snapshot 一致。

## 5. 生成与验收

生成 PDF 时使用环境中可用的 PDF 专用 skill/工具，并遵守其操作标记、输出路径和验证要求。最低验收标准：

1. 生成后把每一页渲染成 PNG，逐页检查中文字体、截字、重叠、对齐、页码与图表可读性。
2. 用 PDF 解析工具重新打开成品，确认页数、可提取文字、标题和关键数字。
3. 检查所有页面均明确区分“实测为 0”和“本轮未获取”。
4. 检查快速诊断没有越界增加完整关键词矩阵、90 天路线图、具体 KOL 名单或自动化任务。
5. 只有在零明显视觉缺陷、零事实漂移后才交付最终 PDF。

## 6. 落盘

- PDF 路径与本次修改说明追加写入 `daily/` 和当月 `monthly/`。
- 原始快照、评分 ledger 与 PDF 分开保存；不得用 PDF 反向覆盖原始证据。
- 同一天重做报告时使用清晰版本名，避免覆盖用户已确认的旧版本。
