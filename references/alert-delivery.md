# 告警与报告投递

## 投递渠道

投递渠道按模块1 **Q8** 的答案决定，配置写在 `configs/tenants.yaml` 每租户的 `slack_dm` / `email` 字段。

- 常规巡检报告 → 对话内原文 Markdown，或按 Q8 选定的渠道
- 需要留档的完整报告 → 邮件 PDF 附件
- P0/P1 告警 → 红色/橙色告警卡片

## 告警卡片结构

```
🔴 [P0] {租户} 舆情告警 · {YYYY-MM-DD HH:mm CST}
────────────────────
📍 信源：{平台} · {原文链接}
📊 曝光量级：{数字，注明统计口径}
🗣 核心指控：{≤50字，引用原文}
⚠️ 判定依据：{为什么是 P0}
🎯 建议动作：
   1. {动作} · 责任方 · 时限
   2. ...
📎 证据：{snapshot 路径}
```

## 熔断告警

采集链路失败时（交互式任务重试 2 次仍失败）：

```
🚨 信源熔断 · {租户}
失败信源：{source}
错误：{error}
已重试：2 次
影响：本次 {模块} 缺 {维度} 数据
⛔ 已终止任务，未使用推测数据填充
```

## 🔴 外发授权

任何外发（Slack 消息、邮件、DM、发帖）**必须先在对话里确认收件人与内容**再发送。

如果用户已建立定时任务，且在创建时明确授权了固定收件人，该任务可走预授权渠道；
**除此之外一律先确认**。预授权的范围仅限当初确认过的渠道与收件人，不得外推到其他人。

## 配置

`configs/tenants.yaml` 内每租户的 `slack_dm` / `email` 字段。
未配置时：告警在对话中输出，并提示「未配置投递渠道，仅在此显示」。
